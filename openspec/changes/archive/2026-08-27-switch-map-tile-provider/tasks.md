- [x] 1.2 Rodar `npm run lint` e `npm run build` e verificar que ambos completam sem erro — ambos passam limpos
- [x] 1.3 (Achado durante a verificação, fora do escopo original) Corrigir a causa raiz real do mapa aparecer em branco: o `maplibre-gl` v6 cria seu Worker de parsing de tiles com uma URL vazia sob o Turbopack (`new Worker("", {type:"module"})`), fazendo o navegador tentar carregar o HTML da própria página como script do worker — travava o carregamento de qualquer tile vetorial, em qualquer provedor, silenciosamente (sem nenhum evento de erro do MapLibre). Era a causa real do "Failed to load module script" que aparecia a sessão inteira, erroneamente descartado antes como ruído da extensão React DevTools. Corrigido chamando `setWorkerUrl("/maplibre-gl-worker.mjs")` (API oficial do MapLibre pra esse cenário) apontando pro worker copiado pra `public/` via `scripts/copy-maplibre-worker.mjs` (novo script `postinstall`, mantém a cópia sincronizada com a versão instalada do pacote) — confirmado no browser real do usuário: erro sumiu, ruas/prédios aparecem de verdade
